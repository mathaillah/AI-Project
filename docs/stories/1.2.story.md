# Story: Implement Specific Error Handling in OCR Service

**Status:** Draft

**Story:** As a developer, I want to implement robust, specific error handling in the OCR service so that different failure modes (e.g., unreadable image, Tesseract error) can be clearly identified and handled by the system.

**Acceptance Criteria:**
1. The `ocr_service` raises a custom `OCRError` exception when Tesseract fails to process an image.
2. The `ocr_service` raises a `PreprocessingError` if an image cannot be read or preprocessed by OpenCV.
3. The `/process-cv` API endpoint in the `ocr_controller` catches these specific exceptions.
4. If `OCRError` is caught, the API returns a `422 Unprocessable Entity` status with a clear error message.
5. If `PreprocessingError` is caught, the API returns a `400 Bad Request` status with a clear error message.
6. Unit tests are created to verify that the correct exceptions are raised and the API returns the correct status codes.
